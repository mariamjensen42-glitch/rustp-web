# Blog API 未完成功能 - Product Requirement Document

## Overview
- **Summary**: 完善 Blog API 系统，补充媒体管理、定时任务调度、用户头像上传等功能，提升系统的完整性和可用性
- **Purpose**: 解决当前系统功能不完整的问题，提供更完善的内容管理和用户体验
- **Target Users**: 开发者、内容创作者、系统管理员

## Goals
- 完成媒体上传、下载、删除功能
- 实现自动调度发布功能
- 添加用户头像上传功能
- （可选）邮件通知功能
- （可选）缓存功能
- （可选）搜索优化

## Non-Goals (Out of Scope)
- 不实现复杂的 CDN 集成
- 不实现实时聊天功能
- 不实现前端界面
- 不实现完整的全文搜索引擎集成
- 不实现支付功能

## Background & Context
当前 Blog API 是一个基于 Rust 和 Actix-web 的后端系统，已经实现了基本的文章管理、用户认证、评论、分类标签等功能。但在 CODE_WIKI.md 中列出了 6 个待完成功能：媒体上传、自动调度发布、用户头像上传、邮件通知、缓存、搜索优化。

从代码分析来看：
1. 媒体功能在 handlers.rs 中有被注释的实现代码
2. 调度发布目前仅支持标记功能，没有实际的定时任务
3. 用户表有 avatar 字段，但没有专门的上传功能

## Functional Requirements

### FR-1: 媒体管理
- 用户可以上传图片等媒体文件
- 用户可以查看已上传的媒体列表
- 用户可以删除媒体文件
- 媒体文件存储在本地文件系统
- 支持基础的文件类型和大小验证

### FR-2: 自动调度发布
- 系统定期检查待发布文章
- 到达预定时间自动将文章状态更新为已发布
- 调度任务在后台持续运行

### FR-3: 用户头像上传
- 用户可以上传个人头像
- 头像与用户账户关联

### FR-4: (可选) 邮件通知
- 评论回复时发送通知邮件
- 文章发布时发送通知

### FR-5: (可选) 缓存
- 热门文章进行缓存
- 减少数据库压力

### FR-6: (可选) 搜索优化
- 优化搜索查询性能
- 提供更准确的搜索结果

## Non-Functional Requirements

### NFR-1: 性能
- 媒体上传应能处理至少 10MB 的文件
- 调度任务检查间隔不超过 1 分钟
- 缓存响应时间不超过 100ms

### NFR-2: 安全
- 文件上传应验证文件类型和大小
- 不允许上传可执行文件
- 用户只能访问自己的媒体文件（除管理员外）

### NFR-3: 可靠性
- 调度任务失败应记录日志
- 媒体文件操作失败应有适当的错误处理

## Constraints
- **Technical**: 使用 Rust 和 Actix-web，数据库使用 SQLite
- **Business**: 优先实现媒体管理、自动调度发布和用户头像上传功能
- **Dependencies**: 现有的数据库表结构和代码架构

## Assumptions
- 媒体文件存储在本地文件系统即可，不需要 CDN
- 定时任务在服务器启动时自动启动
- 用户头像可以复用媒体上传功能

## Acceptance Criteria

### AC-1: 媒体上传功能
- **Given**: 已登录且有上传权限的用户
- **When**: 上传合法的图片文件
- **Then**: 文件成功保存到文件系统，记录保存到数据库
- **Verification**: programmatic
- **Notes**: 需测试文件类型和大小限制

### AC-2: 媒体列表查看
- **Given**: 已登录且有权限的用户
- **When**: 请求媒体列表
- **Then**: 成功返回已上传的媒体列表
- **Verification**: programmatic

### AC-3: 媒体删除功能
- **Given**: 已登录且有权限的用户
- **When**: 删除指定媒体
- **Then**: 文件从文件系统删除，记录从数据库移除
- **Verification**: programmatic

### AC-4: 自动调度发布
- **Given**: 有设置调度时间的文章
- **When**: 到达预定发布时间
- **Then**: 文章状态自动更新为已发布
- **Verification**: programmatic

### AC-5: 用户头像上传
- **Given**: 已登录用户
- **When**: 上传头像
- **Then**: 用户的 avatar 字段更新为头像文件路径
- **Verification**: programmatic
